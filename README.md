# BBDL Online

The Beta Beer Dye League — league site, live stat tracker, and record book for
a Beta Theta Pi chapter.

Built to be handed down. If you are the new commissioner and just want to run a
season, you don't need this file: sign in and read **Admin → Guide**, which is
written for you. This file is for whoever maintains the code.

## Stack

| | |
|---|---|
| Framework | Next.js (App Router) + TypeScript |
| Styling | Tailwind |
| Database & auth | Supabase (Postgres + magic-link auth) |
| Hosting | Vercel |

## Running it locally

```bash
npm install
npm run dev
```

You need a `.env.local` with the Supabase project's URL and anon key:

```
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

The anon key is public by design — it ships in the browser bundle. What protects
the data is Row Level Security, not secrecy. **Never put the `service_role` key
in this file or anywhere in the repo.**

```bash
npm test        # schedule generator, turn order, bracket builder
npm run typecheck
npm run build
```

## How it's put together

**`supabase/migrations/`** — the schema, in order. This directory is the record
of what the database looks like; apply changes as migrations rather than editing
tables by hand, or the next maintainer inherits a database nobody can rebuild.

**`lib/`** — the logic worth testing on its own:

- `schedule.ts` — round-robin generation, no repeated matchups
- `turn-order.ts` — whose throw it is
- `bracket.ts` — playoff seeding
- `queries.ts` — shared, per-request-cached reads
- `supabase/` — server, browser and middleware clients

**`app/(public)/`** — the landing page. Reads no league data at all.
**`app/(app)/`** — everything behind a login.
**`app/(app)/admin/`** — commissioner only.

## Two rules that hold the whole thing together

**1. No stat is ever stored pre-computed.**

Every number on the site is a database view over the `throws` table — one row
per throw. Points per outcome and what counts toward accuracy are columns
generated by Postgres, so a displayed figure cannot disagree with the throws
behind it.

The previous version of this site stored player stats that were invented from
the team score (`cups = score × 0.7`, and so on). That is exactly what this rule
exists to prevent. If you find yourself adding a table to cache a statistic,
add a view instead.

**2. The database enforces the rules, not the UI.**

RLS decides who can read and write what. Triggers decide the sequence number of
a throw, which team a fifa scores for, when a game becomes final, and which
fields a member may change about himself. The app is a convenient way to reach
the database, never the thing standing between a member and the data.

That means a bug in a React component cannot corrupt the league, and it means
you can trust the numbers even though the client holds a public key.

## Deploying

Push to `main`. Vercel builds and deploys it.

Environment variables live in the Vercel project settings — the same three as
`.env.local`, with `NEXT_PUBLIC_SITE_URL` set to the real domain.

Supabase needs that domain in **Authentication → URL Configuration** (Site URL,
and `https://<domain>/**` under Redirect URLs), or sign-in links will not come
back to the site.

The email templates for **Magic Link** and **Confirm signup** should point at:

```
{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=magiclink
```

This matters more than it looks. The alternative (`{{ .ConfirmationURL }}`) uses
a flow that stores a verifier in the browser, which breaks whenever someone
requests a second link — and fails completely when a link is opened on a
different device from the one that asked for it. Everyone reads email on their
phone. Use the token hash.

## Ownership

The Vercel, Supabase and GitHub accounts belong to a superadmin, listed in the
in-site guide. Nothing about running a season requires them — that's the point —
but they are the recovery path if the chapter ever locks itself out.
